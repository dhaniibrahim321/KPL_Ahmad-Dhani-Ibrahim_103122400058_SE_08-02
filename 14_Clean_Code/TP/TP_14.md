## Soal
Kode ini tampak baik dan bagus, tetapi menyalahi beberapa prinsip kode bersih. Bisakah kamu melakukan refaktorisasi? Dimodifikasi dari [amrrwael/Delivery-website-Hits](https://github.com/amrrwael/Delivery-website-Hits).

Sebagai konteks, fungsi di bawah ini menampilkan rincian pesanan di modal dan jika klik konfirmasi, sistem apa menyimpannya.
```js
function fetchOrderDetails(orderId, token) {
    fetch(`https://example.com/api/order/${orderId}`, {
        headers: {
            'Authorization': token
        }
    })
    .then(response => {
        if (!response.ok) {
            throw new Error('Failed to fetch order details');
        }
        return response.json();
    })
    .then(order => {
        // Display order info
        const modal = document.getElementById('orderModal');
        const detailsDiv = modal.querySelector('#orderDetails');
        detailsDiv.innerHTML = '';

        const header = document.createElement('h3');
        header.textContent = `Order ID: ${order.id}`;
        detailsDiv.appendChild(header);

        const status = document.createElement('p');
        status.textContent = `Status: ${order.status}`;
        detailsDiv.appendChild(status);

        // Show modal
        modal.style.display = 'block';

        // Setup close button
        const closeBtn = modal.querySelector('.close');
        closeBtn.addEventListener('click', () => {
            modal.style.display = 'none';
        });

        // Setup confirm button
        const confirmBtn = modal.querySelector('#confirmOrderBtn');
        if (order.status === 'Delivered') {
            confirmBtn.style.display = 'none';
        } else {
            confirmBtn.addEventListener('click', () => {
                confirmOrder(order.id, token);
            });
        }
    })
    .catch(error => {
        console.error('Error:', error);
    });
}
```

## Deskripsi
Meskipun kode yang diberikan dapat berjalan sesuai fungsinya, terdapat beberapa masalah yang menyebabkan kode kurang memenuhi prinsip clean code dan sulit dipelihara jika aplikasi berkembang.

1. Fungsi memiliki terlalu banyak tanggung jawab (Single Responsibility Principle)
Fungsi `fetchOrderDetails()` melakukan banyak pekerjaan sekaligus, yaitu:

- Mengambil data pesanan dari API.
- Memvalidasi respons API.
- Menampilkan detail pesanan ke modal.
- Mengatur tombol close.
- Mengatur tombol konfirmasi.
- Menampilkan modal.

Akibatnya fungsi menjadi panjang dan sulit dipahami.

2. Penggunaan `.then()` yang bertingkat secara berurutan sehingga alur eksekusi menjadi kurang jelas. Semakin kompleks proses yang dilakukan, semakin sulit membaca dan melakukan debugging.

```js
fetch(...)
  .then(...)
  .then(...)
  .catch(...)
```
3. Manipulasi DOM bercampur dengan logika bisnis
Kode yang berhubungan dengan pengambilan data API bercampur dengan kode tampilan (UI). Hal ini membuat perubahan pada tampilan dapat memengaruhi logika bisnis dan sebaliknya.

4. Hardcoded Value
Terdapat nilai yang ditulis langsung di dalam kode seperti:

```js
'https://example.com/api/order/'
'Delivered'
```
Jika nilai tersebut berubah, pengembang harus mencari dan mengubahnya secara manual.

5. Event Listener berpotensi ditambahkan berulang kali
Setiap kali fungsi dipanggil, event listener baru akan ditambahkan pada tombol close dan confirm.

closeBtn.addEventListener(...)
confirmBtn.addEventListener(...)

Hal ini dapat menyebabkan fungsi dieksekusi berkali-kali ketika tombol ditekan setelah modal dibuka berulang kali.

Penjelasan Refactoring

Untuk mengatasi permasalahan tersebut, dilakukan beberapa refactoring.

1. Memecah fungsi menjadi beberapa fungsi kecil
Fungsi besar dipecah menjadi beberapa fungsi dengan tanggung jawab yang lebih spesifik:

- `getOrder()` = mengambil data dari API.
- `showOrderModal()` = menampilkan modal.
- `renderOrderDetails()` = menampilkan detail pesanan.
- `setupCloseButton()` = mengatur tombol tutup.
- `setupConfirmButton()` = mengatur tombol konfirmasi.

Dengan cara ini setiap fungsi memiliki satu tanggung jawab yang jelas.

2. Menggunakan async/await
Kode:
```js
fetch(...)
  .then(...)
  .then(...)
  .catch(...)
```
kita ubah jadi:
```js
try {
    const order = await getOrder(orderId, token);
    showOrderModal(order, token);
} catch (error) {
    console.error(error);
}
```
Penggunaan async/await membuat alur program lebih mudah dibaca karena terlihat seperti kode sinkron biasa.

3. Memisahkan logika bisnis dan tampilan
Proses pengambilan data dipisahkan dari proses manipulasi DOM.

4. Menggunakan konstanta
Nilai yang sering digunakan disimpan dalam konstanta:
```js
const API_URL = "https://example.com/api/order";
const DELIVERED_STATUS = "Delivered";
```
Cara ini meningkatkan keterbacaan kode dan memudahkan perubahan konfigurasi di masa depan.

5. Menggunakan onclick
Daripada terus menambahkan event listener baru setiap kali modal dibuka:
```js
confirmBtn.addEventListener(...)
```
digunakan:
```js
confirmBtn.onclick = () => {
    confirmOrder(order.id, token);
};
```
Sehingga event lama akan digantikan dan tidak terjadi penumpukan handler.
